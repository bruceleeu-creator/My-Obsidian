# 密钥安全与凭证管理

> 来源：2026-08-25 realclaudian `data.json` 密钥泄漏事件复盘 + W35 服务器安全维护盘点。原则先立住，整改执行时机另行确认。

## 核心原则
1. **密钥不入库**：源码、笔记、插件配置、示例、测试里都不留可用的密钥字面量。凡是能被 push / sync 的地方，默认视为公开。
2. **统一安全存储**：密钥只从环境变量或密钥服务读取；新项目 / 新功能从第一天就按这个规范接入（如 W36 发票溯源的密钥存储改造），不等存量整改。
3. **泄漏应急三步**：先作废轮换涉事密钥 → 再清理泄漏载体（git 历史重写）→ 最后全面扫描公开仓库确认无残留。顺序不能反——只删代码不轮换等于没处理。
4. **整改宁可慢、不可漏**：一次清一个面（Obsidian 端 / GitHub 端 / 各项目），每一步可回退；低峰期逐系统轮换，新旧密钥短暂并行，出问题立即回退。

## 检查清单（新功能 / 新项目上线前）
- [ ] 代码、配置、文档中搜索无明文 key / token / 密码
- [ ] 密钥经环境变量或密钥服务注入，本地与线上来源一致
- [ ] `.gitignore` 覆盖所有含密钥的本地配置文件（如 `data.json`）
- [ ] 示例与测试使用占位符或 mock，不使用真实凭据

## 适用场景
- 任何新功能需要接第三方 API（先立密钥规范，再写调用代码）
- 开源 / 公开仓库推 push 前的敏感信息自查
- 密钥泄漏事件发生后的应急处置
