# 开发工作方式

从实战中沉淀的开发经验，保证项目可持续维护、协作顺畅。

## 核心原则
1. **上下文文档先行**：写 AGENT.md 和 README 很重要——让新来的 AI / 人能快速上岗，不用重新解释。文档到位了，交接成本和返工率都会大幅下降。
2. **表述必须清晰**：说不清就先查清楚再写（参考 mattpocock 的清晰表达）。模糊表述会传染整个项目，AI 和同事都会照着错误理解干活。
3. **先页面后逻辑**：vibe 先设计页面 HTML，再填前后端开发，专注功能打通。先把界面和交互跑通、视觉定稿，再补背后的数据与逻辑，避免返工。
4. **文档写明推送方式**：在文档里写清推送地址和命令，防止新人被代理 / 权限问题拦截。一次写明白，省得每次交接都重新踩一遍代理和鉴权的坑。
5. **用 Obsidian 写 AI 开发手册**：把开发手册、定时任务类文档直接落在 Obsidian 里（可版本管理、可双机同步、可被 Claudian 直接读取执行）。文档即系统，不用另起一套工具链。

## 适用场景
- 新项目初始化：先搭好 AGENT.md + README，再开始写代码
- 与 AI 协作开发：上下文文档先行，让 AI 一次就位
- 团队知识交接：文档写明推送/部署方式，新人少踩坑
