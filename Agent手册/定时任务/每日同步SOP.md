# 每日同步 SOP（定时任务操作手册）

> 你是被定时任务唤起的 agent。用户（Bruce）不在场，这份文件就是你的行动准则。
> 执行前**必读**：[[Claudian.md/AGENT|AGENT 协作上下文]]（系统结构 + 双推细则 + 隐私红线）。
> 目标一句话：**把 Bruce 昨天在库里做的所有修改，同步到全部相关文档，然后提交推双远程。**

## 🧭 核心原则（先记住再动手）

1. **只同步，不代写**。Bruce 写的事实（干了什么、勾了什么）→ 同步到下游；Bruce 的主观内容（感受、复盘、评分）→ **永远不替他填**，留空留给本人。
2. **缺记不补造，骨架可预填**。Bruce 的事实与主观内容（干了什么、感受、勾选）永远不代写、不编造；但**当日日志文件本身**要在每次运行时预填好骨架（Step 1.5），正文一律「（待填写）」留给本人。历史缺档的日志不补建（仅 Bruce 明确要求时补，如 9-13）。
3. **拿不准就不动**。执行表 §0 有言在先：过期任务先问再动、风险只追加不删除。定时运行时问不了人，所以拿不准的一律**不改**，写进运行记录等 Bruce。
4. **隐私红线**：本库 GitHub 远程是**公开仓库**。提交前扫一眼改动内容，出现密码 / 密钥 / 身份证 / 手机号 → 停下，不提交，写进运行记录。
5. **永不手动 `git add`**：`.claudian/`、`.obsidian/workspace*.json`、`database.sqlite`（已在 .gitignore，`git add -A` 不会带上，别画蛇添足单独加它们）。
6. **未决事项不执行**。带 🔒「等 Bruce 确认」标记的事（如 W35 安全整改）只在原处待着，定时任务无权启动。

## 📋 每日流程

### Step 0 · 读上下文（1 分钟）
- 读 [[Claudian.md/AGENT|AGENT.md]]：当前是哪个 Cycle、哪周、什么状态
- 确定今天日期、当前周任务页（`任务/周任务/2026-Www.md`）与执行表（`执行2026/2026-Www 周计划执行表.md`）

### Step 1 · 侦察改动（自上次同步以来 Bruce 做了什么）
```bash
git status                     # 未提交的（上次定时运行可能留了尾巴，一并收尾）
git pull --ff-only origin main # 多机共用 main，开工先拉齐（另一台机器可能推过；有未提交改动冲突就停下写运行记录）
git log --oneline -5           # 上次同步点
git diff HEAD                  # 看具体改了什么
git log --since="2 days ago" --name-only --oneline   # 近两天的提交涉及哪些文件
```
把变更文件按目录归类，对号入座下面的流水线：
- `任务/日志/` → 走 Step 2
- `知识卡片/raw/`、`知识卡片/raw/skill+有趣的开源项目/` → 走 Step 3
- `创作区/开发灵感/` → 走 Step 3 的立项分支
- 其他（模板、README、目标、执行表本身被 Bruce 直接改了）→ Step 4

**没查到任何内容改动** → 仍执行 Step 1.5 预填当日日志，再跳到 Step 6 写运行记录收工。

### Step 1.5 · 预填当日日志（2026-09-14 起，Bruce 指定加入）
检查今天的日志 `任务/日志/YYYY-MM-DD.md` 是否存在：
- **不存在 → 按 [[Claudian.md/模板/日志模板|日志模板]] 新建骨架**：frontmatter（`date` / `week` / `type: log`）+ 所属周链接 + 「今日重点」+ 收件箱 + 日志记录三板块（全部写「（待填写）」）+ 底部 dataview 汇总。`week` 取当日所属 ISO 周（如 `[[2026-W38]]`），周任务页没建也不影响（链接悬空正常）。
  - **今日重点预填口径**：工作日 → 从当周任务页挑已排期的 1-2 件写进去（只搬现成的，不发明任务）；周末 → 只写一行「周末休息日：不排任务」；周期/周切换日（周任务页未建）→ 写一行「Cycle-N 启动规划：建周期文件 + 周任务」占位，另留空行给 Bruce 回填
  - 正文三板块永远「（待填写）」，绝不代写
- **已存在 → 不动**（Bruce 自建或此前已预填过，哪怕正文空着）
- 本步骤产物随本次运行的同步改动一起提交

### Step 2 · 日志 → 下游同步（核心链路）
找到昨天（及最近缺同步的几天）的日志，把其中「事实性进展」向下游同步：

| 下游文件 | 同步什么 | 触发条件 |
|---|---|---|
| `任务/周任务/2026-Www.md` | ① 任务勾选 `[x]`＋完成日期；② 「贯穿 · 每日学习」行追加当日打卡（如 `9/11 ✅`）；③ 新增加塞任务写进「加塞」板块；④ 「交付里程碑」表更新状态 | 日志提到对应任务完成 |
| `执行2026/2026-Www 周计划执行表.md` | 按**它自己 §0 的约定**改：任务状态枚举（todo/in_progress/done/blocked）、frontmatter `status`/`updated`/`priority_p0_complete`、§6 里程碑、有决策意义的事追加 §9 决策日志；风险只追加不删除 | 同上 |
| `Claudian.md/AGENT.md` 「🧭 当前状态」 | 有分量的事（任务提前/延期完成、周期切换、新立项、系统变更）才更新快照，顺手把 `updated` 改当天 | 大事才动，小事不动 |
| `目标/十二周周期/2026-Cycle-N.md` | 周期级目标完成、项目状态变化 | 周期级事件才动 |
| `任务/日志/日志合集 *.md` | **平时不碰**。仅在 Cycle 收官切换、或 Bruce 明确要求时才做合并（合并规则见合集头部说明：原文保留、去 frontmatter 和 dataview、标题降级、缺记不补） | 周期节点或明确指令 |

### Step 3 · 知识流水线（raw → wiki）
1. **raw 有新素材**（`知识卡片/raw/` 下 Bruce 新丢的文件）：
   - 一个主题提炼一篇 wiki：`知识卡片/wiki/<主题名>.md`，frontmatter 带 `type: wiki` + 分类标签
   - 提炼 = 归类、合并重复、补全结构，**保留 Bruce 的原始信息量，不注水**
   - 素材够多时可并入已有 wiki 卡（如「开源效率工具集」续加条目），不硬开新卡
   - 提炼后在 `知识卡片/raw/README.md` 的「现有素材」登记对应关系；源文件标 `done`（**不删**，删除留给 Bruce）
2. **`skill+有趣的开源项目/` 有新东西**：同上，通常并入 [[知识卡片/wiki/开源效率工具集|开源效率工具集]]
3. **`创作区/开发灵感/` 有新灵感**：不提炼成 wiki（那是项目灵感不是知识），只确认它被相关文档链接到（新立项 → 周任务里出现引用即可，没有也别硬塞）

### Step 4 · 其他板块
- 日志「收件箱」里有 Bruce 分流过的内容（指向 raw / 周任务 / 周期）→ 确认目标位置真的存在对应内容，缺了才按 ACT 分流补
- 「顺延与暂缓」「待办/未决」里的 🔒 项 → 只核对状态描述是否过时，**不执行**
- 模板、README 被 Bruce 改了 → 检查 AGENT.md 的「数据结构速查」是否需要跟着对齐

### Step 5 · 提交（先检查再动手）
```bash
git status && git diff --stat          # 复核本次要提交的全部改动
# 扫一眼 diff 内容：无敏感信息 → 继续；有 → 停，写运行记录
git add -A
git commit -m "<type>: <中文描述，写清楚同步了什么>"
```
- type 按库规：`feat`（内容同步/新卡）/ `docs`（文档系统）/ `fix` / `refactor` / `chore`
- 一个 commit 只干一件事：日志同步、wiki 提炼分开提交

### Step 6 · 双推（完整细则见 [[Claudian.md/AGENT|AGENT.md]]「📤 双远程备份细则」）
```bash
# Linux（主力机，2026-09-28 起定时任务在本机跑）：
git push origin main                                              # 本机 origin = Gitea（SSH），直推
git push git@github.com:bruceleeu-creator/My-Obsidian.git main    # GitHub 未配远程名，SSH 直推（id_ed25519 已绑定账号）

# Windows / Mac 参考写法：
git push origin main                                  # 首选默认代理
git -c http.proxy= -c https.proxy= push origin main   # 报 via 127.0.0.1 时用（清晨 Clash 多半没开，可直接用这个）
git push gitea main                                   # Gitea 走域名 HTTPS，一般直推成功
```
- GitHub 直连**间歇可用**，失败重试 2-3 次；仍失败 → **本地提交保留**，写进运行记录「待 Bruce 手动推」，不算事故
- Gitea 失败 → 先 `git ls-remote gitea main` 排查，多半是服务器/nginx 的事，记录即可
- 两边都推成功后 `git status` 应干净

### Step 7 · 写运行记录（必做，哪怕今天什么都没干）
在 [[Agent手册/定时任务/运行记录|运行记录]] **顶部**追加一条（倒序，最新在上）：
```
## 2026-09-12 07:00
- 发现：9-11 日志新增，T02 提前完成 + 新灵感 1 条
- 同步：W37 勾选 T02、执行表状态 done、AGENT.md 快照更新
- 提交：a1b2c3d（已双推）/ 推送：GitHub 直连重试 2 次成功
- 没做：X（原因：拿不准 / 涉密 / 未决事项）
```
这份记录是 Bruce 醒来后的验收凭据，也是定时任务可审计的关键。
